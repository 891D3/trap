# M0（工作台 MVP）需求评估

> 日期：2026-10-13 ｜ 评估对象：BRD v0.2 里程碑 M0（F1 壳 + F2 待办 + F3 信息记录 + F4 快捷入口）
> 结论先行：**无阻塞性技术风险，建议通过评估并进入 PRD**。工作量估算 11–15.5 人日。

---

## 1. 价值评估

- **F2 待办 / F3 信息记录 / F4 快捷入口**直接对应 BRD §1 的三大痛点（随手记待办、信息沉淀归档、常用入口快速跳转），是最快产生日常使用价值的功能集。
- **F1 工作台壳**是 F5–F10（项目、辅助区、看板、AI、工作流）的共同载体，三栏结构 + 事件通道定型后，后续功能均为增量。
- MVP 先行可尽早验证「mygo 宿主 + typed IPC + SQLite」主链路，把最大的架构不确定性（框架成熟度）前置暴露。

## 2. 可行性评估（关键查证，2026-10-13）

### 2.1 mygo 框架（github.com/egoist/mygo）

- **版本与活跃度**：v0.4.8（2026-10-12 发布），1807 stars，48 open issues，MIT，main 分支当日有推送——活跃维护中。
- **Typed IPC 已证实**（docs/bindings.md）：`mygo.Bind(service)` 暴露 Go 服务；`mygo.NewEvent[T]` + `Emit`（单窗口）/`Broadcast`（全窗口）类型化事件；`*mygo.Channel[T]` 流式回传；`mygo generate` 从 Go 代码生成 TS 客户端（类型单一事实源，与 BRD 4.3 决策一致）。
- **sqlite 插件已证实**（plugins/sqlite/README.md）：purego 加载预编译库，**免 cgo/免 C 编译器**；SQLite 3.53.4，FTS5/JSON/RTree 启用，**外键默认开启**，支持参数化查询与原子事务；打包应用不运行时下载原生库；Go 侧可不经插件注册直接 `sqlite.Open`（符合 AGENTS.md「SQL 只在 store 层」约束——前端不需要经 sqlite 插件访问库）。
- **官方插件清单**与 BRD 4.2 记载一致：fetch/websocket/sqlite/updater/terminal/glass/game。
- **脚手架**：`npx mygo-cli init my-app`（Go 1.27+，前端工具链支持 Bun/npx），web 前端模板开箱即用。
- **需注意**：
  - 0.x 版本号，1.0 前 API 可能变动 → 锁定具体版本升级；
  - `mygo generate` 通过构建并运行 app 来生成客户端 → dev/CI 流程需脚本化适配。

### 2.2 Milkdown 编辑器（F3 选型复核）

- `@milkdown/crepe` 与 `@milkdown/kit` 均为 **7.22.3**（2026-10-10 发布），MIT，无 peerDeps，React 项目可直接引入。
- Crepe 自带依赖含 `vue`/`katex`/`codemirror`/`dompurify`（`/` 菜单等 UI 为包内自实现）——与 React 并存不冲突，仅有体积冗余；PRD/实现期需在 React 中验证 Crepe 初始化与样式。
- GFM 表格可视化编辑支持（`/` 插入、增删行列）；合并单元格/单元格内嵌套块为 markdown 格式固有限制，BRD F3 已声明能力边界并以 HTML 表格导出兜底。
- markdown-first 存储（SQLite 存纯 markdown 文本）与导出 `.md` 零转换，与 F3 设计一致。

**可行性结论：关键技术依赖均已查证可用，无阻塞项。**

## 4. 依赖清单（新引入，附理由）

**Go：**
- `github.com/egoist/mygo` v0.4.8 —— 宿主框架：窗口/WebView/typed IPC/打包/签名更新一体，替代自研 RPC/WS 与更新器（理由充分）。

**前端（npm）：**
- `react` / `react-dom` / `typescript` / `vite` —— 基础栈（mygo 模板默认）。
- `@milkdown/kit` + `@milkdown/crepe` 7.22.3 —— F3 编辑器（选型已在 BRD F3 确认，MIT）。
- 测试框架（`vitest` + `@testing-library/react`）—— PRD 时确认。

**SQLite：** 经 mygo sqlite 插件，Go 侧直用，无额外 Go 依赖。

> 以上均未涉及云服务/遥测，符合 AGENTS.md 数据本地化硬约束；自动更新（M2）下载源仅限本项目 GitHub Releases。

## 5. 风险与缓解

| # | 风险 | 缓解 |
|---|---|---|
| 1 | mygo 0.x API 变动 | 锁定 v0.4.8；升级前读 CHANGELOG，typed IPC 代码集中、变更面可控 |
| 2 | `mygo generate` 需运行 app 生成客户端 | 脚手架阶段脚本化（dev 前置生成步骤）；CI 中验证 headless 可行性 |
| 3 | Crepe 内部依赖 vue 与 React 并存 | 预期仅体积冗余；实现早期做集成冒烟，异常则降级用 `@milkdown/kit` 自组 UI |
| 4 | 首次构建需下载 sqlite 预编译库（联网+SHA-256 校验） | 开发期一次性；打包后运行时不下载，不违反数据本地化 |
| 5 | 删除/覆盖不可逆（待办、记录） | PRD 明确删除策略（二次确认或软删），E2E 覆盖 |
| 6 | 仓库尚未 git init，硬约束要求 feature 分支开发 | 脚手架第一步即 git init + main 分支保护约定 |

## 6. 开放问题（进入 PRD 时逐条确认）

1. 辅助区（日历/便签/消息流，F6 属 P1）在 M0 的壳中是否仅做**占位**？
2. 待办/记录删除策略：二次确认 vs 可恢复（软删）？
3. 用户资料（头像/姓名）存储位置（SQLite 单表即可，假设单用户，BRD 开放问题 5 沿用）。
4. 数据目录默认位置（`~/Library/Application Support`？）与「设置中可改」的迁移行为。
5. F4 打开本地工具路径的安全边界（仅允许用户显式录入的路径，禁止动态拼接）。
6. M0 是否顺带落地「动态消息流」的最小事件通道（Go→前端事件已可用，仅 UI 占位 vs 展示基础事件）。

## 7. 结论与建议

- **通过评估**：价值明确、技术可行、无阻塞风险，工作量 11–15.5 人日可接受。
- **建议下一步**：产出一份 **M0 PRD**（覆盖 F1–F4 + 数据层约定 + 验收标准），确认后进入脚手架搭建。
- PRD 需优先细化：F3 编辑器集成细节、删除策略、开放问题 1/6（辅助区与消息流在 M0 的边界）。
