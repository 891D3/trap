## 为什么这样做（含被否决的备选方案）

- spark 卡直接展示摘要行 content（N1 已把 content 加进 NoteSummaryV2）——避免为每张卡发一次 GetNoteV2；被否决的备选：卡片懒加载正文（交互复杂，收益低）。
- 预览态用 `pointer-events:none` 覆盖（复用 Milkdown 渲染产物）而非独立渲染器——零依赖 & 状态一致；被否决的备选：markdown-to-html 前端 renderer（重复实现渲染逻辑）。
- 删除当前笔记后自动打开列表下一条（若有）——v2 列表常驻且打开态延续的设计语义；验收注记（E2E 断言同步放宽为「下一条或空态」），devlog 记录该口径变化。
- 标签统计走 Go 端 TagStats（service 直接读全量笔记正文计数）而非前端多次 getNote：一次 IPC 完成统计。
- 运行增强：spark promote 后 store 侧 loadSparks 主动刷新（事件可能晚于 UI 查询）。
