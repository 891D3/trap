# 2026-10-14 UI 调整：辅助区仅看板可见 + 信息记录大编辑器布局

## 做了什么

- 分支：`feature/m0-ui-aux-note`，基于 T5 提交 `4b81a28` 创建。
- `web/src/App.tsx`：
  - 辅助区（`<Auxiliary/>`，日历/便签/动态消息流）仅在 `view === 'dashboard'` 时渲染；宽屏直接显示，窄屏抽屉与 MainArea 的「辅助区」切换按钮（`showAuxToggle={narrow && view === 'dashboard'}`）也仅看板出现；
  - 移除看板中间的「看板 · M2 开放」占位（用户确认），看板视图主体即辅助区；顺带移除不再使用的 `IconDashboard` 导入。
- `web/src/panels/views/NoteView.tsx`：
  - 布局反转为「中间默认大编辑器（flex:1）+ 右侧 280px 记录列表（可收起/展开）」；
  - 工具栏新增「收起列表/展开列表」切换按钮（`aria-label="切换记录列表"`，图标 IconCollapse/IconExpand）；收起后编辑器占满中间；
  - 「全部/已归档」筛选标签移入右侧列表面板；
  - 进入视图后自动打开最近一条记录（列表按创建时间倒序取首条，`autoOpenedRef` 防重复触发），使中间默认呈现编辑器；
  - 无选中记录（如空库或删除当前记录后）时显示空态 + 「新建记录」入口。
- E2E（`e2e/m0_e2e.go`）：
  - 新增 `runLayoutFlow`：看板视图断言 `.aux` 存在且不再有「看板 · M2 开放」占位；待办视图断言 `.aux` 不存在；
  - `runNoteFlow` 新增收起/展开断言：点击「收起列表」后 `.note-card` 消失且 `.note-editor-panel` 仍在，点击「展开列表」后卡片恢复。

## 为什么这样做（含被否决的备选方案）

- 辅助区改为看板专属是用户明确要求（「其他功能下都去掉」），宽/窄屏两条路径同步收窄，避免窄屏在其他视图仍可拉出辅助区。
- 记录列表收起状态用会话内 `useState`（契约明确不做跨会话持久化）；默认展开以兼容既有流程与 E2E。
- 自动打开最近一条记录满足「中间默认是大大的编辑器」；被否决的备选：进入视图自动新建记录（会积累垃圾记录）。
- `openNote` 未列入 useEffect 依赖并注明原因（每次渲染重建的普通函数 + ref 保证只触发一次），避免行为依赖依赖数组。
