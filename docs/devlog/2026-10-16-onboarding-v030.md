# 2026-10-16 Onboarding 首次安装初始化（v0.3.0）

## 做了什么

（分支 `feat/onboarding`；D1–D5，按用户裁定「首次安装需输入用户名、初始化目录」）

- **D1 目录策略**（`internal/onboarding/`）：数据目录统一迁移到 `~/.trap`（含 `copies/`、`exports/` 子目录）；首次启动检测旧 userData（`~/Library/Application Support/Trap/trap.db`）且新库不存在 → 自动迁移（复制 → SQLite 探针校验可打开 → 旧库 `rename` 为 `.bak-migrated` 备份保留）；迁移失败回退旧路径、不丢数据、不阻塞启动。`homeDirFor`/`legacyDirFor` 注入点支持测试隔离。
- **D2 初始化判定与 IPC**：`settings` 表新增 `app.initialized` 键；`AppService.IsInitialized`/`Initialize`（原子写 用户名/主题/导出目录/initialized 四键 + 广播 settings.changed）/`BackfillInitialized`（存量用户：有 `user.name` 无标记 → 静默补 true）；`OpenDataDir`/`PickDirectory`（原生目录选择器，白名单命令）。
- **D3 初始化页 UI**（`OnboardingView.tsx`）：点阵底图 + 居中白卡（图标圈 + 「欢迎使用 Trap」+ 副标题 + 表单 + 全宽主按钮）；表单项 = 用户名（必填/回车提交）、导出目录（原生选择器）、主题偏好（浅/深/跟随系统）、数据目录只读展示 + 打开目录。
- **D4 前端接线**：App 拦截（`appInitialized===false` → 初始化页；`settingsLoading` → 空白防闪烁）；完成后 `completeOnboarding` → store 翻转标记 → 切主界面数据看板；移除默认姓名硬编码 `'Eric'`。
- **D5 E2E**：`runOnboardingFlow`（独立 `-onboarding` 入口，未初始化库）：显示初始化页 → 空用户名按钮禁用 → 填名提交 → 进入数据看板 + 姓名生效 + 服务端 initialized=true → 重载不再显示。既有 8 流程回归全绿。

## 为什么这样做（含被否决的备选方案）

- 目录迁移「复制 → 校验 → rename 备份」而非直接 move：move 遇目标盘跨卷/失败会留下半迁移状态；复制+校验后 rename 旧库（非删除）保证任何一步失败都能回退。
- 迁移判定用「新库不存在 且 旧库存在」而非时间戳：幂等（重复启动不重迁），且新旧路径天然区分。
- `initialized` 标记放 settings 表而非 schema_migrations：业务态非结构态；存量兜底用「有 user.name 即视为老用户」而非「有任意数据」，避免全新安装被误判。
- E2E onboarding 独立 `-onboarding` 入口而非并入主流程：主流程库已预置 initialized（既有用例假定已初始化用户），未初始化场景需独立库 + 独立进程。
- 目录选择器走 `mygo.Dialog.Open({Directory:true})`（原生 sheet）而非自绘 UI：平台一致、零依赖；被否决的备选：前端手绘目录树（复杂且非原生）。
