# 2026-10-15 R5 待办视图重构（快速创建/日期分组/行内编辑/辅助区四卡）

## 做了什么

（分支 `feature/r5-todo`，基于 R4 提交 675b605）

- **输入解析**（`web/src/api/todo-parse.ts`，纯函数）：时间短语（今天/明天/后天/大后天/周X/星期X/礼拜X + HH:mm / HH点(半)?；只写时间默认今天；无法识别不建 due_date——PRD 拟定决策 2「宁缺勿错」）与 `#词` 项目匹配（精确/非空白前缀）、`#` 查询词提取、本地时间 → UTC RFC3339。覆盖 Go 单测无法覆盖的 UI 解析口径；时间断言在 E2E 按本机时区折算。
- **store 扩展**：`addTodoFull/editTodo`（带分类/日期/项目创建与全量更新）、`auxDateFilter/auxCategoryFilter`（月历/按属性与列表卡联动过滤态）。原 `addTodo(title)` 保留（看板快速添加用）。
- **TodoView 重写**（按 ui-baseline §5.3 / 设计稿 15:11）：
  - 快速创建卡：多行 textarea（Enter 换行，⌘/Ctrl+Enter 提交——PRD 拟定决策 7）、`#` 联想浮层（240 宽 Popover，选项含色点/#名称/N 项待办）、日期/项目 chips（可移除）、分类圆点单选（个人/工作/学习）、「添加待办」主按钮、空内容 `[role=alert]` 保留；
  - 列表卡：全部/今天/已完成 Tab（计数、active 下划线沿用 .filter-tab）；未完成按日期分组（今天含过期红点警示/明天/以后/未安排，组头色点+「N 项」组标+组间分隔线——过期并入今天为拟定决策 3）；条目行 = 复选框 + 标题（点击进编辑）+ #项目（项目色文字）+ HH:mm + hover 删除（二次确认不变）；行内编辑态（标题输入 + 日期/项目 chips + 分类单选 + 取消/保存，Esc=取消）；
  - `⌘/Ctrl+K` 聚焦快速创建（v1.1 决策 3 落实）；
  - 过滤 chips：侧栏项目点击 → projectFilter；月历日期点击 → auxDateFilter；按属性看 → auxCategoryFilter；均可单独移除。
- **辅助区四卡**（`panels/aux/TodoAux.tsx`）：月历（月切换/今天钮/事件点 #9DB0C4/今日主色圆/选中浅底/点击过滤联动列表）、按属性看（三行分类计数筛选）、按项目查看（色点/名称/未完成计数，点击切待办视图沿用过滤态）、即将到来（未来 3 条有日期未完成，34×34 日期块+周X+时刻）。
- **E2E**：
  - `setInputAndPressEnter` 改为 textarea setter + Ctrl+Enter（决策 7）；
  - 完成/恢复断言适配分组结构：完成后切「已完成」Tab 断言恢复钮 aria-checked=true（同步窗口同口径），恢复后切「全部」Tab 断言（不再依赖已完成项出现在未完成列表）；
  - 新增 `runTodoV2Flow`：种子项目 → 输入「明天 15:00 测试解析」断言 chip 与明天分组 + 服务层 due_date 精确等于本机时区折算的 UTC RFC3339 + 分类 work；输入 `#前端` → 浮层联想点击 → 提交 → 服务层 project_id 断言 + 条目显示 #项目文本；行内编辑改标题保存 + 服务层断言；月历点击明天格 → 过滤 chip ≥2 → 清除日期 chip。

## 为什么这样做（含被否决的备选方案）

- 解析在输入时实时进行（parsed memo）而非提交时：「明天 15:00」在输入中即时呈现 chip 所见即所得，与设计稿一致；被否决的备选：提交时才解析（用户看不到识别结果，可控性差——正是用户本轮要求避免的）。
- 列表「已完成」不再混入全部组（v1 分区显示）：设计稿为分组+单独已完成 Tab；E2E 需要切 Tab 断言是设计行为变化（已记录）。
- 行内编辑点击整行标题（button.todo-text）进入而非专门「编辑」按钮：设计稿点击条目即展开编辑行；复选框与删除按钮保持独立不误触。
- category 默认 'work'：设计稿默认态/快捷创建示例均为工作类；空 category 语义保留在 Go 侧兼容 v1 数据。
- 月历「同一名义的下个周X」策略（nextWeekday 同名→下周）与 PRD 口径一致；「过期并入今天」在行内编辑只展示不改 dueDate（R5 范围暂无日期修改控件，date chip 只读展示——行内「取消安排」被简化为仅展示，日期编辑延后至用户使用反馈再定）。
