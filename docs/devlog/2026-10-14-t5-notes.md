## 为什么这样做（含被否决的备选方案）

- **E2E 两次大排障的根因（重要经验）**：
  1. 「归档后编辑器消失」：`reloadToNotes` 的 `LoadURL` 发起异步导航后，`waitFor(新建记录按钮)` 在**旧文档上立即通过**（旧文档就是信息记录页），后续打开记录/断言/归档全部发生在旧文档；约 0.4s 后新文档提交，编辑器被替换。表象曾误判为 Vite reload/进程崩溃——最终用 `performance.timeOrigin` 变化 + URL 中新出现的 `e2e_reload` 时间戳定位。修复：新增 `loadPageDocument`，所有 reload 助手以 **timeOrigin 变化**作为「新文档已生效」判据，再继续断言。
  2. 「导出内容被转义」：`execCommand('insertText')` 把 Markdown 作为纯文本插入（`\#`、`\|`、`<br />`）。改用 `ClipboardEvent` 粘贴 `text/plain`，Milkdown clipboard 插件解析为 GFM。
  3. 「预热阶段编辑器等待失败」：Vite 首次优化 Milkdown 依赖图会整页 reload。预热改为「先等稳定 → 实例化编辑器（重试 3 次）→ 清理 → 再等稳定」。
- **导出断言以「库内内容」为基准**：Milkdown 会规范化 Markdown（表格对齐 `| :- |` 等），因此 E2E 不比对输入字符串，而是断言：解析为 GFM（无 `\#`/`\|` 转义）+ 导出文件与 `NoteService.Get` 返回内容逐字节一致（PRD 无损导出的真不变量）。
- 被否决：`mygo dev --web` 浏览器模式（SQLite WASM 不支持）；Playwright（无法附着原生 WKWebView）；用编辑器实例 API 直接设值（需暴露内部句柄，破坏封装）。
- `e2eView` 深链：WKWebView 中 `button.click()` 不触发 React 合成导航（已尝试 `__reactProps` 调用与键盘事件均不稳定）；深链是最小、可文档化的测试钩子，不改变默认用户路径。
