# 2026-10-13 T3.1 设置真实接入

## 做了什么

- 分支：`feature/m0-settings-integration`，基于 T2 提交 `522d25c` 创建。
- 新增 `web/src/api/app-settings.ts`：统一封装 `AppService.getSettings`、`updateProfile`、`setTheme`、`setExportDir`；归一化 Go 端 `omitempty` 缺省字段；将未知/英文底层错误转换为中文用户提示。
- 新增 `web/src/realtime/settings-events.ts`：统一订阅 `settings.changed`，组件不直接连接 mygo Events。
- 重构 `web/src/state/app-store.tsx`：
  - Provider 启动时从 Go 加载设置；
  - 姓名、头像路径、主题、导出目录、数据目录由状态驱动；
  - 设置保存采用乐观更新，失败回滚并保留中文错误；
  - 事件更新可覆盖跨窗口变化；请求期间事件版本保护避免旧响应覆盖新事件；
  - 主题不再使用 localStorage，改以 Go SQLite 为事实源；首次空库仍展示 Eric/system 默认值但不自动写回。
- 重构 `web/src/panels/views/SettingsView.tsx`：姓名失焦/回车保存、主题持久化、数据目录只读展示、导出目录文本编辑与失焦/回车保存、加载/保存错误提示。
- 导出目录本轮按契约采用手动输入；原生目录选择器与打开数据目录留后续 Go typed IPC 任务。
- 新增 `e2e/settings_e2e.go` 与 `e2e/run-settings.sh`，`npm run test:e2e` 驱动真实 macOS WKWebView；测试使用临时 SQLite 文件，不写开发者用户数据。

## 为什么这样做（含被否决的备选方案）

- API 与事件分别放在 `web/src/api/`、`web/src/realtime/`：遵守 AGENTS.md 的 RPC/事件集中管理约束，组件只依赖状态层。
- 设置状态集中在 `AppStoreProvider`：保留 `useStore`/`useTheme` 对外接口，避免 Sidebar、App 和其他视图感知 IPC 细节。
- 主题移除 localStorage：T3.1 已有 Go 持久化事实源；旧 mock/localStorage 数据不迁移，符合契约假设。
- 未引入 Vitest/testing-library：仓库当前无前端测试脚手架；本轮使用真实 WKWebView E2E 覆盖用户可见设置流程，并以 `normalizeSettings`/`toChineseError` 纯函数、严格类型检查和生产构建作为补充验证。
- 未修改 `web/src/mygo.ts`：协议未变，`npm run generate` 验证产物 up to date。
