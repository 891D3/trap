# 2026-10-18 待办句中时间丢字修复 + 已完成项可编辑

## 做了什么

分支 `fix/todo-parse-done-edit`（自 main `5b0c80a`），两项用户反馈修复：

### 需求 1：快速创建句中时间字符丢失

用户输入「明天下午，去学校，从6:20开始参加班级的晚自习」，保存后标题变成「下午，去学校，从 开始参加班级的晚自习」——「明天」「6:20」被剥离，正文出现空洞。

根因在 `web/src/api/todo-parse.ts` 的 `extractDue`：

1. **日期词剥离过宽**：`明天` 只要不在字段值语境（前面无 `：:】`）就剥，不判断它是否属于叙述正文。「明天下午，去学校…」里「明天」是叙述的一部分，单剥后留下悬空的「下午」。
2. **句中时刻剥离**：`6:20` 位于句子中间（前有「从」后有「开始」），剥离把句子打断。

修复（`web/src/api/todo-parse.ts`）：

- **日期词剥离收敛为「安排前缀」判定**：仅当
  - 后文**紧邻**时刻短语（`明天 15:00 测试解析`、`明天6:20交作业`、`明天下午3点`），或
  - 日期词位于句尾/行尾/后接标点（`明天交报告`、`明天，去…`→ 等等，标点分支已由后续正文判断兜住），
  且不在字段值语境（前面是 `：:】`）时才剥离；否则保留在正文（chip 已表达日期信息）。
- **句中时刻只建 chip 不剥正文**：命中位置两侧都是正文文字（如「从6:20开始」）时保留原文；句首/句尾/紧跟日期词或标点的时刻短语仍剥（`下午3点开会` → `开会` + chip「今天 下午3点」）。
- 标签时间（`# 开始时间：14:00`）维持只建 chip 不剥正文的既有行为（0.3.1 引入，本次确认保留）。

### 需求 2：已完成待办可编辑

「已完成」Tab 中点击任务标题无法进入编辑。

勘察结论：前端 `TodoView` 的阅读态点击对所有行（含 done）都走 `setEditingId`，无 CSS 拦截、无 Go 侧状态清理路径；真实 E2E 实测（新增回归流程）确认**点击已完成标题即可进入行内编辑、保存后标题落库且 done/completed_at 保持**——即 0.3.1 的行内编辑重构后该能力实际已存在，用户截图场景是旧版本行为。以新增 E2E 断言固化，防回归。

### E2E（`e2e/m0_e2e.go`）

新增 `runTodoParseRegressionFlow`（在 v2 流程后执行）：

1. 快速创建输入用户原文 → 断言落库标题**包含**「明天」和「6:20」（丢字回归护栏）+ chip due_date 为明天 06:20（本机时区折算 UTC）。
2. 勾选完成 → 切「已完成」Tab → 点击标题进入行内编辑 → 改标题保存 → 断言标题落库且 `done=true`、`completed_at` 非空。

## 为什么这样做（含被否决的备选方案）

- **否决：剥离后用占位符补洞**（如「从  开始」→「从 __ 开始」）——正文出现机器填的符号更怪；不如保留原文。
- **否决：句中时刻一律不剥**——「明天 15:00 测试解析」这类真安排前缀会被保留成噪音标题，破坏 0.3.0 已有行为与既有 E2E 断言。最终采用「紧邻才剥」的折中，探针（node --experimental-strip-types 直接跑真实 todo-parse.ts）验证 10 个用例收敛。
- **否决：为需求 2 改前端代码**——真实 E2E 证明行为已符合预期，无代码可改；补断言固化即可。不臆造修复。
- 修复策略两轮收敛：第一版 `followedByTime` 用全文搜索导致「明天」仍被剥（6:20 在句中也被当紧邻），收紧为 `afterDay` 开头紧邻匹配后探针全绿。
